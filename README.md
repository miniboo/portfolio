## Casual entry screen

The portfolio, direct résumé route and alternate `/2/` route share a small password entry screen. A successful entry unlocks all three for the current browser tab using a base-path-scoped `sessionStorage` marker; reloads preserve that tab's access. Another tab/session starts at the entry screen. The default HTML state and critical inline CSS hide the page before scripts run, preventing a content flash. Wrong entries show an accessible error; the form supports Enter, manages focus and clears the password after entry. The input's 1px bottom rule changes from neutral to portfolio coral `#ff5c39` on focus, without thickening or adding a rectangle. JavaScript and HTTPS (or localhost) are required. If browser storage is unavailable, the current page can still open but another route may ask again; the limitation is reported rather than silently remembered.

**This is a casual viewing screen, not security or access control.** The page HTML, public source repository, scripts, résumé content and media remain directly readable. The client-side SHA-256 digest can be brute-forced, and the session marker or display rules can be bypassed. The supplied password is not stored in source or browser storage; only its verification digest is committed. No encryption or server authentication is claimed. Email PDF exports exclude the entry screen and remain ungated.
